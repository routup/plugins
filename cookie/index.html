@routup/cookie ​

Reads request cookies and writes Set-Cookie headers in a routup app. The Cookie header is parsed once per request with cookie-es; you set and clear cookies with typed attributes instead of hand-built header strings.

Requirements ​

  • Node.js 24 or later, ESM only
  • routup ^6.3.0 (peer dependency)

Installation ​

bash
npm install @routup/cookie

Quick Start ​

ts
import { App, defineCoreHandler } from 'routup';
import { cookie, setResponseCookie, useRequestCookie } from '@routup/cookie';

export const app = new App();

app.use(cookie());

app.get('/', defineCoreHandler((event) => {
    const visits = Number(useRequestCookie(event, 'visits') ?? 0) + 1;

    setResponseCookie(event, 'visits', String(visits), { httpOnly: true, sameSite: 'lax' });

    return { visits };
}));

cookie() is a plugin: register it with app.use() before the routes that read cookies (Plugins). The file exports the app; serve it from your entry file.

bash
curl -i http://localhost:3000/ -H 'cookie: visits=3'
# HTTP/1.1 200 OK
# set-cookie: visits=4; Path=/; HttpOnly; SameSite=Lax
#
# {"visits":4}

Default Behaviour ​

StepWhat happens
ParseThe middleware parses the Cookie header and stores the result on the request; the read helpers only read that store, so changing the header later has no effect
SkipWhen cookies are stored already, by an earlier cookie() or by setRequestCookies(), it does not parse again
DecodeEach value is decoded with decodeURIComponent; a value that does not decode is kept as sent
DuplicatesFor a name sent more than once, the first value wins
WritesetResponseCookie() appends one Set-Cookie header per call, with Path=/ unless you pass another path; it needs no plugin

Handlers that run before cookie() see no cookies: useRequestCookies() returns {} and useRequestCookie() returns undefined. Cookies are not signed or encrypted, so treat every request cookie as client input.

The Set-Cookie headers are set on event.response, so a route that returns a Response object of its own sends none of them.
