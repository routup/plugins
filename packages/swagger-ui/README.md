## Why @routup/swagger-ui?

[`swagger-ui-dist`](https://www.npmjs.com/package/swagger-ui-dist) ships the Swagger UI bundle as static files, but its `index.html` points at the Petstore demo and assumes it is served from the site root. To show your own document under `/docs`, you serve the bundle, write your own HTML page with the spec and a correct `<base href>`, and keep both in sync when you mount the app elsewhere or behind a proxy.

| Concern | Without it | With @routup/swagger-ui |
|---------|-----------|-------------------------|
| Static bundle | You serve `swagger-ui-dist`'s folder yourself (and hide its `package.json`, README, source maps, …) | Only the files the page references are served from `node_modules` through `@routup/assets`; everything else goes to the next handler |
| HTML page | You copy and edit `index.html` to load your document | The page is generated with your document embedded (file or object) or with its URL |
| Content security policy | The stock page needs an inline script and style | The page has no inline script or style; `csp: true` sends a policy built from your document |
| Mount path | Asset links break when the UI moves from `/` to `/docs` or into a nested router | `<base href>` is derived from the mount path of the request, including parent routers |
| Reverse proxy | You hard-code the public prefix in the HTML | `basePath` or `baseURL` prefixes the `<base href>` |
| UI configuration and OAuth | You edit the inline script | Swagger UI options, `oauth` and `authAction` are passed as plain options |

```typescript
import { App } from 'routup';
import { swaggerUI } from '@routup/swagger-ui';

const app = new App();

app.use('/docs', swaggerUI('./openapi.json'));
```

## Installation

```bash
npm install @routup/swagger-ui --save
```

ESM only, Node.js `>=22`, peer dependencies `routup@^6.1.0` and `@types/swagger-ui-dist@^3.30.5` (for the option types). `swagger-ui-dist` and `@routup/assets` are installed as dependencies.

## Usage

### Mount the UI

```typescript
import { App, serve } from 'routup';
import { swaggerUI } from '@routup/swagger-ui';

const router = new App();

router.use('/docs', swaggerUI('./openapi.json'));

serve(router, { port: 3000 });
```

Open `http://localhost:3000/docs/` in a browser.

- The UI is mounted under whatever path you pass to `router.use()`. `/docs` and `/docs/` both return the page with `<base href="/docs/">`, so the bundle's relative asset links resolve either way. The OAuth redirect URL defaults to `oauth2-redirect.html` next to that `<base href>`, so OAuth works from both as well.
- Only `GET` and `HEAD` are answered, and only for the files listed in [Served files](#served-files). Other paths and methods under the mount go to the next handler, which answers `404` when there is none.

### Served files

Under the mount path the handler serves:

- the HTML shell at `/` and `/index.html` (the stock Petstore page of `swagger-ui-dist` is never served),
- `swagger-initializer.js` and `index.css`, generated by this package (the bootstrap and the styles; the shell has no inline script or style),
- `swagger-ui.css`, `swagger-ui-bundle.js`, `swagger-ui-standalone-preset.js`, `favicon-16x16.png` and `favicon-32x32.png` from `swagger-ui-dist`,
- `oauth2-redirect.html` and `oauth2-redirect.js` only when an OAuth flow is configured: `oauth` or `oauth2RedirectUrl` is set, or the document passed as object or file declares an `oauth2` or `openIdConnect` security scheme. For a document loaded by URL, set one of the two options.

Every other path (`README.md`, `LICENSE`, source maps, ES bundles, `package.json`, …) and every other method is passed on to the next handler.

### Document sources

You can pass a file path, a parsed spec object or a remote URL:

```typescript
import { App } from 'routup';
import { swaggerUI } from '@routup/swagger-ui';

const router = new App();

// a JSON file, read once when the plugin is created
router.use('/docs', swaggerUI('./writable/swagger.json'));

// a plain object, for example with runtime values merged in
router.use('/internal/docs', swaggerUI({
    openapi: '3.1.0',
    info: { title: 'My API', version: '1.0.0' },
    paths: {},
}));

// a URL the browser fetches at runtime
router.use('/petstore', swaggerUI('https://petstore3.swagger.io/api/v3/openapi.json'));
```

- **File path**: any string that is not an absolute URL with a non-`file:` protocol. It is read synchronously with `JSON.parse` when `swaggerUI()` is called, relative to the process working directory. The document is embedded in the generated `swagger-initializer.js` (`spec`).
- **Object**: embedded in `swagger-initializer.js` as `spec`.
- **URL** (`http:`, `https:`, …): passed to Swagger UI as `url`; the browser fetches it, so it must be reachable from the browser (and allow CORS if it is on another origin).

### Behind a reverse proxy

```typescript
import { App } from 'routup';
import { swaggerUI } from '@routup/swagger-ui';

const router = new App();

// the proxy forwards https://example.com/api/* to this app
router.use('/docs', swaggerUI('./openapi.json', { basePath: '/api/' }));
// <base href="/api/docs/">

router.use('/v2/docs', swaggerUI('./openapi.json', { baseURL: 'https://example.com/api/' }));
// <base href="https://example.com/api/v2/docs/">
```

- `basePath` is prefixed to the mount path; `baseURL` is used as the origin and prefix. When both are set, `baseURL` wins.
- `baseURL` must be an absolute `http:` or `https:` URL; anything else throws when the plugin is created. Its path is treated as a directory: `https://example.com/api` behaves like `https://example.com/api/`.

### Swagger UI options and OAuth

```typescript
import { App } from 'routup';
import { swaggerUI } from '@routup/swagger-ui';

const router = new App();

router.use('/docs', swaggerUI('./openapi.json', {
    docExpansion: 'none',
    persistAuthorization: true,
    oauth: {
        clientId: 'swagger-ui',
        scopes: ['openid', 'profile'],
        usePkceWithAuthorizationCodeGrant: true,
    },
}));
```

- Every Swagger UI configuration field (`SwaggerConfigs`) is serialised into `swagger-initializer.js` and passed to `SwaggerUIBundle`, overriding the built-in defaults. Function values (for example `requestInterceptor`) are passed as source.
- Values of the document and the options are serialised with `<`, `>`, `&`, U+2028 and U+2029 escaped, so a description containing `</script>` or `<!--` cannot break out.
- Bound and native functions (`fn.bind(…)`, `Math.max`) have no source to pass; they throw when the plugin is created.
- `oauth` is passed to `ui.initOAuth()`, `authAction` to `ui.authActions.authorize()`, after the UI is created. `oauth` also serves the OAuth redirect page (see [Served files](#served-files)).
- Without `oauth2RedirectUrl`, the redirect URL is `oauth2-redirect.html` resolved against the page's `<base href>`.

### Layout

The UI uses `BaseLayout`, without Swagger UI's top bar: the page shows the configured document only, with no field to explore other documents by URL. Pass `layout: 'StandaloneLayout'` to get the top bar back, including its field to load any document by URL (see [Upgrading to v5](#upgrading-to-v5)); its logo then needs an inline style, which `style-src 'self'` blocks (the UI still works).

### Content security policy

The shell loads only same-origin files, so it runs under `script-src 'self'; style-src 'self'`. Set `csp: true` to send the recommended policy, or a string to send that policy:

```typescript
import { App } from 'routup';
import { swaggerUI } from '@routup/swagger-ui';

const router = new App();

router.use('/docs', swaggerUI('./openapi.json', { csp: true }));
```

With `csp: true` every response (including `304`s, so a reload keeps the policy) carries:

```
default-src 'self'; script-src 'self'; style-src 'self'; img-src 'self' data: blob:;
media-src 'self' blob:; font-src 'self' data:; connect-src 'self' <origins>;
object-src 'none'; base-uri 'self'; form-action 'self'
```

- `blob:` lets "Try it out" render binary responses (images, audio, video).
- `<origins>` are the absolute origins of the document URL, `configUrl`, the `urls[]` entries, the document's `servers` at root, path and operation level (or Swagger 2 `host`), and its OAuth token, refresh and OpenID URLs.
- Templated server URLs are expanded with the `default` and every `enum` value of their variables (all combinations, at most 64 per server; a server with more is skipped). A protocol-relative server (`//api.example.com`) adds its `https:` and `http:` origin.
- Only origins of the form `scheme://host[:port]` (letters, digits, `.`, `-` or a bracketed IPv6 address) are added; any other server value is dropped.
- The `baseURL` origin is added to every directive except `object-src`.
- With `layout: 'StandaloneLayout'` and a document loaded by URL, the validator badge origin (`https://validator.swagger.io` unless `validatorUrl` is `null` or `'none'`) is added to `img-src`.

Some origins cannot be known in advance; pass a string policy for them: servers of a document loaded by URL, server URLs with a variable that has no default, values a visitor types freely into a server variable (no `enum`), and an OpenID Connect `token_endpoint` found through discovery on another origin than the `openIdConnectUrl`.

To build your own header, reuse the policy:

```typescript
import { buildContentSecurityPolicy } from '@routup/swagger-ui';

const policy = buildContentSecurityPolicy({
    connectSrc: ['https://api.example.com'],
    imgSrc: [],
    origins: [],
});
```

`buildContentSecurityPolicy()` throws for a source that contains whitespace, a control character, `;` or `,`, since it would add a directive or a second policy. Source expressions such as `'self'`, `data:`, `https:` or `*.example.com` are accepted.

### Producing the document

To *produce* the document from decorated controllers, see [`@routup/decorators` → OpenAPI generation](https://plugins.routup.dev/decorators/#openapi-generation): it calls [`@trapi/swagger`](https://github.com/trapi/trapi)'s `generateSwagger()` with the `@routup/decorators/preset`, or uses the `trapi` CLI. Run that at build time, write the spec to `./openapi.json`, and point `swaggerUI()` at the result so production does not recompute it on every boot.

## Options

`swaggerUI(document, options?)` takes the [Swagger UI configuration](https://swagger.io/docs/open-source-tools/swagger-ui/usage/configuration/) (`SwaggerConfigs` from `@types/swagger-ui-dist`; function values such as `requestInterceptor` are passed as source) plus these fields:

| Option | Type | Default | Description |
|--------|------|---------|-------------|
| `basePath` | `string` | none | Path prefix the app is reachable under (behind a proxy). Prepended to the mount path in `<base href>`. |
| `baseURL` | `string` | none | Absolute URL the app is reachable under. The mount path is resolved against it for `<base href>`. Takes precedence over `basePath`. |
| `oauth` | `UIOAuthOptions` | none | Passed to `ui.initOAuth()`: `clientId`, `clientSecret`, `realm`, `appName`, `scopeOperator`, `scopes` (required), `additionalQueryStringParams`, `useBasicAuthenticationWithAccessCodeGrant`, `usePkceWithAuthorizationCodeGrant`. Also serves the OAuth redirect page. |
| `authAction` | `Record<string, any>` | none | Passed to `ui.authActions.authorize()` to pre-authorise security schemes. |
| `csp` | `boolean \| string` | `false` | Set a `content-security-policy` header on every response. `true`: the [recommended policy](#content-security-policy), string: that policy. |
| `spec` / `url` | | set from `document` | Overwritten from the `document` argument; set the document there instead. |

Built-in Swagger UI defaults, each overridable through the options: `dom_id: '#swagger-ui'`, `deepLinking: true`, `presets: [apis, StandalonePreset]`, `plugins: [DownloadUrl]`, `layout: 'BaseLayout'` (see [Layout](#layout)). Setting `oauth2RedirectUrl` also serves the OAuth redirect page.

## API

| Export | Kind | Purpose |
|--------|------|---------|
| `swaggerUI(document, options?)` | function (default export) | Plugin that serves the UI on the path it is mounted at |
| `createUIHandler(document, options?)` | function | The handler the plugin installs, for `router.use()` without the plugin wrapper |
| `isFileURL(input)` | function | `true` when `input` is treated as a file path (no protocol, or `file:`) |
| `buildContentSecurityPolicy(input?)` | function | The recommended policy as a header value; `input` adds `origins`, `connectSrc` and `imgSrc` sources |
| `UIOptions`, `UIOAuthOptions`, `ContentSecurityPolicyInput` | types | Option types |

```typescript
import { App } from 'routup';
import { createUIHandler } from '@routup/swagger-ui';

const router = new App();

router.use('/docs', createUIHandler('./openapi.json'));
```

## Notes

- **Only JSON files.** A file `document` is parsed with `JSON.parse`; YAML is not supported. Convert it first or pass the parsed object.
- **Pass a path, not a `file://` string.** `isFileURL('file:///…')` returns `true`, but the string is then read as a plain path and fails. Use `fileURLToPath()` first.
- **The file is read once.** Changes to the document after `swaggerUI()` was called are not picked up until restart.
- **Functions in options lose their scope.** Options are written into `swagger-initializer.js`; functions (for example `requestInterceptor`) are inserted by their source text, so they cannot use variables from your server code.
- **Install analytics.** `swagger-ui-dist` depends on [`@scarf/scarf`](https://github.com/scarf-sh/scarf-js), whose postinstall script sends install analytics. Set `SCARF_ANALYTICS=false` in the install environment (or `"scarfSettings": { "enabled": false }` in your `package.json`) to disable it.

## Upgrading to v5

- **The top bar is hidden by leaving it out, not by CSS.** The default layout is `BaseLayout`, which has no top bar. Earlier versions used `StandaloneLayout` and hid `.swagger-ui .topbar` with CSS for every layout. With an explicit `layout: 'StandaloneLayout'` the top bar, including its field to load any document by URL, is now visible.
- **The `?url=` query parameter is ignored.** A link such as `/docs/?url=https://evil.example/openapi.json` no longer loads another document; the UI shows the document passed to `swaggerUI()`.
- **Only `GET` and `HEAD` requests for the [served files](#served-files) are answered**; every other path and method goes to the next handler. `oauth2-redirect.html` is served only when an OAuth flow is configured.
- **`baseURL` is validated** when the plugin is created and **bound or native function options throw** there too.
