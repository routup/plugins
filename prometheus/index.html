@routup/prometheus ​

Times every request and serves the metrics for Prometheus to scrape. The plugin records a request duration histogram labelled by method, route pattern and status, plus an uptime gauge, on a prom-client registry that your own metrics can share.

Requirements ​

  • Node.js 24 or later, ESM only
  • routup ^6.4.0 (peer dependency)
  • prom-client >=15.0.0 (peer dependency, required: install it next to the plugin)

Installation ​

bash
npm install @routup/prometheus prom-client

Quick Start ​

ts
import { App, defineCoreHandler } from 'routup';
import { prometheus } from '@routup/prometheus';

export const app = new App();

// first, so every route after it is timed; serves /metrics
app.use(prometheus());

app.get('/users/:id', defineCoreHandler((event) => ({ id: event.params.id })));

prometheus() returns a plugin; register it with app.use() before the routes it times (Plugins). The file exports the app; serve it from your entry file.

bash
curl http://localhost:3000/users/42
curl http://localhost:3000/metrics
# # HELP http_uptime duration (sec) since application is up and running.
# # TYPE http_uptime gauge
# http_uptime 12
# # HELP http_request_duration duration (sec) histogram of http responses labeled with: method, path, status_code
# # TYPE http_request_duration histogram
# http_request_duration_bucket{le="0.003",status_code="200",method="GET",path="/users/:id"} 1
# ...
# http_request_duration_count{status_code="200",method="GET",path="/users/:id"} 1

Default Behaviour ​

Installing the plugin registers two metrics on prom-client's global register, adds a handler that times the requests after it, and serves the registry at /metrics.

MetricDefault nameTypeValue
uptimehttp_uptimegaugeWhole seconds since the plugin was installed, not since the process started
requestDurationhttp_request_durationhistogram (or summary)Seconds per request, labelled method, path and status_code; buckets [0.003, 0.03, 0.1, 0.3, 1.5, 10]

Labels ​

LabelValue
methodThe request method
pathThe pattern of the route that handled the request, composed over every mount (/api/users/:id for GET /api/users/42); for a request no method-bound route handled, the raw path or unmatchedPath
status_codeThe status of the response the handlers after the plugin returned; 200 when they returned none
  • Errors and 404s are recorded as 200. When a route throws and no error handler answers, or no route matches, the plugin gets no response: routup builds the 500 or 404 after the plugin returned. Register an error handler after your routes to record the real status of errors.
  • Requests without a route keep their URL. A request no method-bound route handled, such as a 404, a request answered by middleware or a method-less mount, or a scrape of /metrics itself, is labelled with its raw path: one series per distinct URL. Set unmatchedPath when the app is reachable by arbitrary paths.
  • Mount order matters. A request answered by a handler registered before the plugin is not timed.

Scrape Endpoint ​

The endpoint is mounted with app.use(metricsPath, ...), so it answers every method and every path below it (POST /metrics, /metrics/x) with registry.metrics() and the registry's Content-Type, text/plain; version=0.0.4; charset=utf-8 for the default registry. It is public; Protect the Metrics Route guards it.
