@routup/rate-limit-redis ​

A store for @routup/rate-limit that keeps the hit counters in Redis, so every instance behind a load balancer counts against the same quota and a restart keeps the counters. It talks to Redis through an ioredis client created with redis-extension.

Requirements ​

  • Node.js 24 or later (also required by redis-extension), ESM only
  • routup ^6.3.0 (peer dependency)
  • @routup/rate-limit (peer dependency): the limiter this store plugs into
  • redis-extension ^3.0.0 (peer dependency): package.json marks it optional, but the store imports it when the module loads, so install it
  • ioredis ^6 (peer dependency of redis-extension)
  • A Redis server

Installation ​

bash
npm install @routup/rate-limit-redis @routup/rate-limit redis-extension ioredis

Quick Start ​

ts
import { App, defineCoreHandler } from 'routup';
import { rateLimit } from '@routup/rate-limit';
import { RedisStore } from '@routup/rate-limit-redis';

export const app = new App();

// 100 requests per client every 15 minutes, counted in Redis
app.use(rateLimit({
    windowMs: 15 * 60 * 1000,
    max: 100,
    // without an argument: a client for localhost:6379
    store: new RedisStore(),
}));

app.get('/', defineCoreHandler(() => 'Hello, World!'));

Pass the store as the store option of rateLimit(); every other option, such as windowMs, max or keyGenerator, belongs to the limiter (Configuration). The file exports the app; serve it from your entry file.

The samples on this page need a running Redis. They are type-checked; the tests run them against an in-memory stand-in for the redis-extension client, which pins the key format, the TTL and the reset behaviour described here.

Connecting to Redis ​

new RedisStore(input?) takes one argument:

ArgumentTypeDefaultDescription
inputstring | ClientnoneA Redis URL: the store creates its own client with createClient({ url }). A Client (an ioredis Redis instance, for example from redis-extension's createClient()): the store uses it. Nothing or undefined, for example an unset environment variable: the store creates a client for localhost:6379

The client is created in the constructor, and ioredis connects when it is created unless lazyConnect is set. The store never closes it; call store.client.quit() on shutdown.

ts
import { App, defineCoreHandler } from 'routup';
import { rateLimit } from '@routup/rate-limit';
import { RedisStore } from '@routup/rate-limit-redis';

export const app = new App();

app.use(rateLimit({
    // the store creates its own client for this URL
    store: new RedisStore('redis://user:secret@redis.internal:6379/0'),
}));

app.get('/', defineCoreHandler(() => 'Hello, World!'));

To share the client the rest of your app uses, pass it in:

ts
import { App, defineCoreHandler } from 'routup';
import { rateLimit } from '@routup/rate-limit';
import { RedisStore } from '@routup/rate-limit-redis';
import { createClient } from 'redis-extension';

// the client the rest of the app uses as well
export const client = createClient({ url: process.env.REDIS_URL });

export const store = new RedisStore(client);

export const app = new App();

app.use(rateLimit({ store }));

app.get('/', defineCoreHandler(() => 'Hello, World!'));

Default Behaviour ​

StepWhat happens
KeyThe limiter's key (by default the client IP) is stored as rate-limit:<key>
Countincrement() reads the counter with GET, adds 1 and writes it with SET ... PX windowMs
ExpiryEvery hit writes the key again with a TTL of windowMs, so the TTL starts over on each hit
Reset timeThe resetTime returned to the limiter is now plus windowMs on every hit, so RateLimit-Reset always shows the full window
Readget(), called by the limiter with countAfterResponse, reads the counter with GET and its TTL with PTTL, without writing; a missing key returns undefined
Undodecrement(), called by the limiter for skipFailedRequest or skipSuccessfulRequest, subtracts 1 and writes the key with a fresh TTL; a missing key is left alone
Resetreset() deletes the key. The limiter never calls it; call it yourself (Reset After a Successful Login)

windowMs comes from the limiter: rateLimit() calls init() with its resolved options when it is called, so give each limiter its own store instance.

  • The window slides. A client that sends at least one request per windowMs never sees its counter expire and stays rejected until it pauses for a full window. The default MemoryStore instead clears all counters together every windowMs.
  • Increments are not atomic. GET and SET are two commands, not INCR. Concurrent requests for the same key, from one instance or several, can read the same value and count one hit too few.
  • A refund can land in a later window. increment() returns no window token: a key that expired and was written again holds a plain counter like before, so decrement() cannot tell the windows apart and lowers whatever counter the key holds.
  • decrement() does not wait for Redis. Its SET is not awaited, so an error there is not reported to the limiter.
  • Redis errors fail the request. When GET or SET in increment() fails, for example because Redis is unreachable and ioredis gives up, the error leaves the limiter and the request is answered with 500; it is not let through.

RedisStore ​

The store class. It is also the default export.

typescript
declare class RedisStore implements Store {
    constructor(input?: string | Client);
}
MemberDescription
clientThe ioredis client in use
optionsThe limiter options passed to init()
init(options)Called by rateLimit(); keeps the options
increment(key)Adds 1 to the counter; returns { totalHits, resetTime }
get(key)Reads the counter without changing it; returns { totalHits, resetTime }, with resetTime from the key's TTL, or undefined
decrement(key)Subtracts 1 from an existing counter
reset(key)Deletes the counter
buildKey(key)Protected; returns rate-limit:<key>

Store is the interface of @routup/rate-limit, Client the ioredis client type that redis-extension exports.

Recipes ​

Separate Counters per Limiter ​

Two limiters on the same Redis share the key rate-limit:<ip> and would count each other's hits. A subclass that overrides buildKey() gives one of them its own keys.

ts
import { App, defineCoreHandler } from 'routup';
import { rateLimit } from '@routup/rate-limit';
import { RedisStore } from '@routup/rate-limit-redis';

// keys rate-limit:login:<key> instead of rate-limit:<key>
class LoginStore extends RedisStore {
    protected override buildKey(key: string): string {
        return `rate-limit:login:${key}`;
    }
}

export const app = new App();

app.use(rateLimit({
    max: 100,
    store: new RedisStore(process.env.REDIS_URL),
}));

app.use('/login', rateLimit({
    max: 5,
    store: new LoginStore(process.env.REDIS_URL),
}));

app.get('/', defineCoreHandler(() => 'Hello, World!'));
app.post('/login', defineCoreHandler(() => 'Welcome'));

A POST /login counts once under rate-limit:<ip> and once under rate-limit:login:<ip>; a GET / counts only under rate-limit:<ip>.

Reset After a Successful Login ​

The login limiter counts every attempt. After a correct password the route deletes the counter of the client, so its earlier failed attempts no longer count. The route builds the key with the same function as the limiter.

ts
import type { IAppEvent } from 'routup';
import { App, defineCoreHandler, getRequestIP } from 'routup';
import { rateLimit } from '@routup/rate-limit';
import { RedisStore } from '@routup/rate-limit-redis';

// stands in for a real password check
const PASSWORD = 'secret';

const keyGenerator = (event: IAppEvent) => getRequestIP(event, { trustProxy: true }) ?? '127.0.0.1';

const store = new RedisStore(process.env.REDIS_URL);

export const app = new App();

// five attempts per client every 15 minutes
app.use('/login', rateLimit({
    windowMs: 15 * 60 * 1000,
    max: 5,
    keyGenerator,
    store,
}));

app.post('/login', defineCoreHandler(async (event) => {
    const { password } = await event.request.json() as { password?: string };

    if (password !== PASSWORD) {
        event.response.status = 401;

        return 'Wrong password';
    }

    // a successful login clears the attempts of this client
    await store.reset(keyGenerator(event));

    return 'Welcome';
}));
