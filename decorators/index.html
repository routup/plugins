@routup/decorators ​

Write routup routes as TypeScript classes: @DController() sets the path of a class, @DGet(), @DPost() and the other method decorators bind its methods to routes, and parameter decorators pass the path parameters, headers, body, query or cookies in as arguments. A TRAPI preset reads the same decorators to generate an OpenAPI document.

Requirements ​

  • Node.js 24 or later, ESM only
  • routup ^6.3.0 (peer dependency)
  • @routup/body, @routup/cookie and @routup/query are installed as dependencies. @DBody(), @DQuery(), @DCookie() and @DCookies() need their plugins registered before decorators(): see Decorators and the Parsers
  • For OpenAPI generation only: @trapi/core, @trapi/metadata and @trapi/swagger ^2.3.0 (optional peer dependencies). Only @routup/decorators/preset imports them, so install them where you generate the document. An older @trapi/metadata ignores @DProduces without an error. @trapi/metadata has typescript >=5.0.0 as a peer dependency

TypeScript Settings ​

The package supports legacy (experimental) TypeScript decorators only, the flavour that has parameter decorators. Standard (TC39) decorators, which TypeScript 5 and later compile when experimentalDecorators is off, have no parameter decorators and pass a context object instead of a property name: tsc rejects the controllers (TS1206 Decorators are not valid here, TS1241 Unable to resolve signature of method decorator), and code emitted anyway registers none of the method routes, so a request gets 404. The class middlewares of @DController() still register, so under a guarded controller it gets 401 instead.

CompilerWhat to configure
tsc"experimentalDecorators": true in the compilerOptions of tsconfig.json
esbuild, and tools built on it such as tsxThe same tsconfig.json setting, which the build API and tsx read. The transform API reads no file: pass tsconfigRaw: { compilerOptions: { experimentalDecorators: true } }. Without the setting esbuild fails with "Parameter decorators only work when experimental decorators are enabled"
SWC (also unplugin-swc for Vite or Vitest)jsc.parser.decorators: true and jsc.transform.legacyDecorator: true
Node.js type stripping (node app.ts)Not possible: decorators are not erasable syntax and fail with a SyntaxError. Compile first
json
{
    "compilerOptions": {
        "experimentalDecorators": true
    }
}

emitDecoratorMetadata is not needed: the package reads no design-type metadata. It does no harm when another library requires it.

Installation ​

bash
npm install @routup/decorators

Quick Start ​

ts
import { App } from 'routup';
import {
    DController,
    DGet,
    DPath,
    decorators,
} from '@routup/decorators';

@DController('/users')
class UserController {
    @DGet('/:id')
    show(@DPath('id') id: string) {
        return { id };
    }
}

export const app = new App();

app.use(decorators({ controllers: [UserController] }));

decorators() returns a plugin: register it with app.use() (Plugins). The file exports the app; serve it from your entry file.

bash
curl http://localhost:3000/users/5
# {"id":"5"}

Default Behaviour ​

WhenWhat happens
A class is definedIts decorators store the paths, routes, parameters and middlewares on the class prototype. Nothing is registered yet; getControllerRoutes() can already list the routes
decorators({ controllers }) is calledReturns the plugin; no controller is touched
app.use(decorators(...))Each class in controllers is created with new Controller(), without arguments; an instance is used as it is. Its middlewares and routes are added to the app at the position of this call, under each controller path. Installing the plugin again creates another instance and adds the routes again
A request arrivesThe class middlewares run, then the middlewares of the method's route, each as a new instance; then the parameter values are read and the method is called and awaited
The method returnsThe value becomes the response as for any routup handler; undefined leaves the request unanswered and a thrown error goes to the error handlers (Return Values)

Routes registered before app.use(decorators(...)) for the same path and method answer first, and the parser plugins must come before it.

OpenAPI Generation ​

The @routup/decorators/preset entry tells @trapi/metadata how to read the @D* decorators. @trapi/metadata reads the TypeScript sources with the compiler, it does not run them; @trapi/swagger turns the metadata into the document. Install the three packages where you generate the document:

bash
npm install --save-dev @trapi/core @trapi/metadata @trapi/swagger
ts
import { buildPreset } from '@routup/decorators/preset';
import { generateMetadata } from '@trapi/metadata';
import { Version, generateSwagger } from '@trapi/swagger';

// reads the controllers in the *.ts files below `cwd`; nothing is executed
export async function generateDocument(cwd: string) {
    const metadata = await generateMetadata({
        preset: buildPreset(),
        entryPoint: { cwd, pattern: '**/*.ts' },
        ignore: ['**/node_modules/**'],
    });

    return generateSwagger({
        version: Version.V3_2,
        metadata,
        data: {
            name: 'My API',
            servers: ['http://localhost:3000/'],
        },
    });
}

For the controller of the documentation decorators this writes GET /users/{id} with the tag users, the bearer security requirement and the responses 200, 401 and 404, and POST /users with 201 and 401.

  • In place of buildPreset(), preset also takes the string '@routup/decorators/preset': @trapi/metadata imports the entry and uses its default export.
  • saveSwagger(spec, { cwd: 'writable' }) from @trapi/swagger writes writable/swagger.json; its name and format options change the file name and switch to YAML.
  • Error responses shared by every operation go to generateSwagger() as data.responses, for example responses: [{ name: '401', status: '401', description: 'Unauthorized' }]; an operation's own response at the same status wins.
  • The document is a file or an object: serve it with @routup/swagger-ui. Nothing in @routup/decorators generates it at runtime.

The trapi binary of @trapi/cli takes the preset by name:

bash
npm install --save-dev @trapi/cli
npx trapi generate --preset @routup/decorators/preset --entry-point 'src/**/*.ts' --output swagger.json

What each decorator adds to the document is described with the decorator: @DStatus(), @DProduces(), the documentation decorators and the parameter decorators.

buildPreset() ​

Returns a new preset object for @trapi/metadata. The default export of @routup/decorators/preset is the object buildPreset() returns.

typescript
import type { Preset } from '@trapi/core';

declare function buildPreset(): Preset;

Change the returned object to adjust the preset, for example to leave out a parameter decorator, and pass it as preset:

ts
import { buildPreset } from '@routup/decorators/preset';

// leave @DHeaders() parameters out of the document
export const preset = buildPreset();

preset.parameters = preset.parameters?.filter((handler) => handler.match.name !== 'DHeaders');

The preset knows the decorators of this package by name, plus DAll (documented as GET), DHead and DOptions. A custom decorator with another name works at runtime, but needs a handler of its own in a preset built from buildPreset() to appear in the document.
